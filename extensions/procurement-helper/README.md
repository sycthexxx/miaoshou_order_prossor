# 内部采购助手（Chrome，Manifest V3）

仅本地加载，不上架、不分发。不需要启动新的后端服务。

## 安装

1. 在自己的 Chrome 地址栏打开 `chrome://extensions`，打开“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本目录（包含 manifest.json 的 procurement-helper 文件夹）。
3. 刷新工作台页面，从“采购汇总”点击某个商品的“打开货源”。插件会打开 1688，并带入该链接的待采购清单。
4. 每台员工电脑都需要独立连接工作台：先打开实际公司工作台，再点击插件图标。弹窗会带入当前页面的内网地址，点击“保存并授权此工作台”，回到采购汇总确认显示“采购助手已连接 · 0.1.11”。不要填写员工电脑自己的 localhost。授权后会即时连接已打开的工作台页面，必要时刷新一次。

Mac 当前目录：`/Users/es/Develop/GolandProjects/order_processor/extensions/procurement-helper`。

项目修改后执行 `npm run build` 更新工作台；插件修改后在扩展管理页点击“重新加载”，并刷新工作台和 1688 页面。

## 使用

- 浮动按钮可拖动；点击展开/收起。展开后也可拖动面板标题栏，位置保存在当前 Chrome。
- 展示货源商品、规格、需求数量和页面已选数量。数量相等为绿色，超量为橙色，不足显示差额。
- 先在 1688 展开规格并选中颜色。自动识别仅接受完整规格文本匹配，不把“深红色”和“酒红色”视为同一颜色。
- 规格名称不一致时，点击“规格映射”，选择或手动填写实际1688规格。默认颜色共享给同一原颜色的全部尺码，尺码修改仅当前规格；勾选“仅此规格例外”可单独指定。采购映射保存到原工作台后端，按账户与货源商品隔离，与厂家无关。
- 识别到多个数量框时可用“指定数量框”，再点击实际数量框或数量数字。此时插件拦截一次点击，不改变商品数量。按 Esc 取消。
- 指定数量框仍须同时确认颜色、尺码与数量；无法确认时不会强行标绿。网站页面结构不兼容时需调整 DOM 适配器。
- 颜色切换后，本标签页保留已核对数量和颜色状态，并标记“已核对（其他颜色）”；切回对应颜色后重新读取，修改数量会重新计算。切换 Chrome 标签页后也会再次读取。刷新1688页面会清空核对记录。若从其他位置清空所有选择，请点击“清除核对”，避免沿用未显示颜色的旧记录。
- 每个规格展示本地订单 SKU 图，点击放大。缺图或加载失败会明确提示，不拿同商品其他规格的图片代替。升级到 0.1.1 后，需要重启 Go 后端、刷新采购汇总并重新打开货源，旧标签页快照没有图片。
- “重新核对”只重读当前 1688 页面，不刷新采购需求。更新需求需回工作台刷新汇总并重新打开货源。
- **绿色只表示数量核对一致，不表示加入进货单、已下单、已付款。** 插件不点击采购按钮，不修改数量，不记录已采购状态。

## 关联规则

同一账户采购快照内，所有 `detail.1688.com/offer/<商品ID>.html` 链接按商品ID合并；忽略追踪查询参数和卖家。不同货源分别核对。两个账户或两次打开货源生成两个独立标签页快照，不互相覆盖。

传入插件的数据仅包含商品标题、货源链接、规格、数量、账户标签和汇总时间，不包含订单号、买家信息或卖家信息。不把清单放入 URL 查询参数，不向 1688 API 发送采购清单，不读取 Cookie 或请求头。厂家回传通过原工作台标签页的同源请求发给原服务器，不从员工电脑的 localhost 拉取，也不转发1688的Cookie。

从采购汇总正常点击或中键打开仍优先保留独立采购快照；直接打开1688链接、新建/复制标签页时，0.1.9 可按明确选定的工作台账户查询采购缓存。未连接插件时工作台会阻止带清单跳转并给出授权提示；仍可选“仅打开货源（不带采购清单）”。Chrome 完全退出后，内存会话清单失效，可重新从汇总打开或连接工作台查询采购缓存；已保存的采购映射保留在服务器，浮窗位置保留在当前Chrome；“指定数量框”的DOM位置仅当前页面有效。不支持1688短链接、非商品详情地址。

## 文件

- background.js：工作台来源校验、按标签页保存快照、打开对应货源。
- bridge.js：捕获采购汇总链接点击。
- core.js：货源地址、快照校验和数量比较。
- mappings.js：同色共享规则、单SKU例外、旧映射迁移及有效映射解析。
- adapter.js：只读 DOM 数量识别，不调用网站接口。
- content.js：拖动浮窗、规格映射与数量显示。
- options.html/options.js：内网工作台地址配置。

## 0.1.3：页面规格选择与数量操作定位

- 展开“规格映射”时读取当前页面的颜色选项和可见尺码，选择后点击“应用选择”。颜色有图时提供缩略图辅助核对。切换商品颜色后可点“读取页面规格”更新尺码列表；不预设所有颜色具有相同库存或尺码。
- 手动输入框始终保留。未读取到选项时直接手动填写；海军蓝/藏青色等名称差异由人工确认，不做相似词自动替换。
- 在1688输入数量或点击加减按钮，面板会展开并滚动到唯一匹配的SKU，闪烁约2秒。只滚动插件内部，不抢走数量输入框焦点、不滚动1688页面。匹配不确定时不跳转到其他SKU。
- 本次仅修改插件：在 Chrome 扩展管理中重新加载，再刷新1688标签页即可。无需重新启动后端。
- 页面提取与定位测试使用本地模拟DOM；真实1688页面仍需安装后验证，当前工具无法读取该站点。

## 0.1.4：修复数量定位漏触发

新增数量变化检测，不再只依赖加减按钮文字和事件；支持无文字图标按钮。只在相同颜色上下文中检测已识别数量的变化，首次读数、切换颜色及未知读数不触发变化定位。面板标题显示版本 0.1.4，便于确认是否更新成功。重新加载扩展后必须刷新原来的1688页面，旧页面中的脚本不会自动更新。

## 0.1.5：操作即定位闪烁

数量操作与数量核对完全分开：按下加减控件、点击数量框或输入数量时立即定位并闪烁，不等待数值变化或与需求一致。暂时清空输入框、输入尚未完成、数量为零、超量或不足均可定位；标绿仍要求完整有效数量与需求一致。保留数量变化检测作为自定义控件的补充。


## 0.1.6：修复跨电脑空清单，增加厂家回传

### 为什么其他电脑会是空列表

旧版默认只在 localhost/127.0.0.1 注入工作台脚本。员工访问内网IP时，如果没有在该电脑授权此地址，点货源只是普通网页跳转，插件根本没收到采购快照。插件不会从别的电脑读取你原来 Chrome 的临时会话数据。

新版加入工作台握手状态：未连接时明确提示并提供“仅打开网页”替代入口；插件弹窗优先使用当前工作台地址，授权后立即注入，无需把服务器改为 localhost。服务器数据仍通过工作台获取，采购快照通过扩展消息传到新货源标签页。

**升级每台电脑**：将本版完整插件目录复制到那台电脑（包含新增 connection.js、supplier.js），在 `chrome://extensions` 重新加载，刷新工作台和货源页。只更新 Mac 后端不会自动更新员工电脑上加载的插件文件。后端需要更新并重启，以提供厂家回传接口；前端也需使用新构建。

### 厂家回传

有明确账户和货源快照的标签页会处理厂家回传（包括0.1.9直接查询取得清单的页面）。优先读取用户指出的商品页左上角厂家名称：必须同时满足可见左上区域、公司/店铺名称语义元素、其自身商家头部或紧邻容器中的1688店铺链接，不能只凭坐标判断。另支持明确当前商品卖家区域。唯一可信名称连续两次稳定出现时，自动回传商品ID和厂家/店铺名称。全页泛名称、推荐卡、页脚或无法确认归属的名称仅作为手动候选，不自动写入。真实1688 DOM尚未获工具访问授权，所以这部分适配需实际安装验证；不保证每种1688布局都可自动识别。

浮窗“厂家 / 店铺”区域可手动填写、重新读取和回传。“重新读取”进入人工确认模式，不会后台悄悄提交。识别重试有限，成功后停止。回传失败会显示原因；原工作台标签页必须保持打开，若已关闭或跳到其他网站，请重新从采购汇总打开货源。旧后端404会提示更新并重启后端。

当前规则：同一货源的厂家名称与本次回传名称相同时保持不变；名称不同时更新为本次厂家。目标同名1688厂家存在就复用，不存在才新增；旧厂家记录保留，不把不同名称的厂家合并。更新完成后手动刷新工作台的采购汇总或卖家列表查看。

验证包括：跨电脑实际origin选择、已授权动态脚本注册、按源账户/源服务器回传、厂家跨offer拒绝、工作台关闭/离站错误、同源fetch、旧后端404、候选归属与数量核对回归。均为本地代码/模拟DOM测试，不代表真实1688页面或第二台电脑已Live通过。


## 0.1.7：同名保持，不同名更新厂家

厂家回传不再一律保留已有指定。按当前账户、1688货源商品逐项处理：没有关联则新增关联；名称相同则保留原关联与更新时间；名称不同则复用或新增本次名称的厂家，并更新货源关联。旧厂家记录不会删除。此规则也适用于此前人工指定的厂家，请确认自动识别或手动输入的名称是本次要使用的厂家。

浮窗分别显示新增关联、更新关联和同名保持的结果。旧后端缺少更新结果字段时会提示更新并重启后端，不会把旧规则当作新规则成功。升级时更新后端并重启，将完整0.1.7插件目录同步到每台电脑重新加载，再刷新工作台并重新打开货源。厂家识别来源要求、人工确认入口和原服务器/原账户隔离保持不变。


## 0.1.8：同色只改一次，采购映射保存到服务器

例如把“浅咖啡,L”映射为“浅咖,L”，同一货源的“浅咖啡,M”“浅咖啡,S”立即使用“浅咖,M”“浅咖,S”，以后新出现的“浅咖啡,XL”也自动继承。颜色规则仅在当前账户的当前货源商品内生效，不串到其他货源或账户。

默认方式无论下拉选择还是手动输入整规格，颜色部分都会共享，尺码部分仅修改当前SKU。例如填写“浅咖,1XL”，当前L变为1XL，其他M/S仍保留自身尺码。只有勾选“仅此规格例外”才单独覆盖整规格；已有明确例外不会被普通共享颜色修改覆盖。

- “重置此规格”：取消该SKU例外/特殊尺码/本页数量框定位，继续继承共享颜色。
- “重置同色映射”：清除该原颜色的共享规则及同色所有SKU例外、特殊尺码，恢复原规格。其他颜色不变。
- 共用同一份有效映射进行数量识别、核对与操作定位闪烁。改颜色后同步更新相关行的输入/选项，清除受影响的旧核对记录和DOM数量框定位。

映射通过原工作台标签页读取和保存独立采购配置，不改店铺产品、订单或同步原始数据，重新同步不会覆盖。只有服务器成功响应后才显示“已保存到服务器”。修改后立即保存；断网/原工作台关闭时明确提示失败并保留本页修改，可重试。读取失败时禁止修改保存，避免用空配置覆盖已有规则。

其他电脑重新从同一账户采购汇总打开相同货源会读取同一份服务器映射。返回窗口时会检查远端最新配置；如果当前存在尚未应用的输入/下拉草稿或保存失败修改，则不会自动覆盖。可手动“读取服务器（放弃未保存修改）”重新载入。两电脑同时修改时使用版本号检查；冲突会阻止覆盖，并要求先重新读取最新版。

旧版Chrome本地逐SKU映射不会自动写回服务器。仅当服务器从未保存过（revision=0）且本机有旧配置时，显示“导入本机旧映射”按钮；点击后将一致颜色合并为共享规则，保留特殊尺码。旧记录同一颜色存在不同目标时先保留各自旧别名，不猜测；重新设置一次共享颜色即可统一，旧别名不再覆盖新规则。服务器已有版本（包括已清空但revision>0）不会再次导入旧配置。

升级：更新并重启后端，每台电脑更新完整0.1.8插件目录（含mappings.js）并重新加载，刷新工作台，再从采购汇总重新打开货源。旧标签页无法自动获得新脚本。无需改原商品数据，也无需重新采集订单。

验证：36项本地插件测试覆盖共享颜色、各尺码保留/例外、重载及新增SKU、旧迁移、DOM定位不进入服务器、原服务器/账户/商品隔离、乐观锁冲突，以及数量识别/定位回归。真实1688页面和多电脑Live联调仍需安装后验证，不将模拟测试视为实站通过。


## 0.1.9：直接打开货源查询采购缓存

原有“采购汇总 → 打开货源”路径保持不变，已带入的标签页快照优先，切换查询账户不会自动改写它。

每台电脑先授权实际工作台地址，在采购汇总选择账户和“包含赠品”范围，点击“设为插件查询账户”。正常点击打开货源也会记住本次明确上下文。之后直接打开 `https://detail.1688.com/offer/商品ID.html`，插件通过原工作台同源桥接，按商品ID查询这个账户的采购缓存；没有选定账户时不会猜第一个账户，也不会连接员工电脑的 localhost。

原工作台标签页关闭时，点击浮窗“连接工作台并查询”，插件会在后台打开已授权服务器的工作台并连接，保留此前选择的账户。切换账户：浮窗“切换查询账户”打开工作台，选择账户/赠品范围后点击“设为插件查询账户”，再回浮窗点击查询。直接查询的标签页可重新读取缓存；已有汇总带入快照不被此操作替换。无待采购货源时显示明确说明与缓存时间。

后端汇总按账户和赠品选项分别保存在内存，第一次读取时生成；只有采购页面“刷新采购汇总”按钮重算。打开商品、切页、切账户、插件重新查询都不强制刷新；后端重启后内存缓存自然重新生成。界面和快照的时间均为后端缓存生成时间。直接查询清单同样支持厂家回传和独立采购映射，目标仍绑定原服务器/账户。

升级：更新并重启Go后端，构建前端；各电脑更新完整插件目录，扩展页重新加载0.1.9，并刷新工作台与1688页。需保持已授权服务器可访问。模拟测试覆盖选择上下文、原快照优先、缓存查询、无命中、关闭工作台重连及源隔离；未进行真实1688站点或第二台电脑实测。


## 0.1.10：核对状态显示采购总件数

浮窗底部显示“0/1 个规格数量一致 · 共需 6 件”。总件数取当前采购清单各规格需求数量之和，不是1688已选数量，也不会刷新采购缓存。窄屏可换行。重新加载插件后刷新1688页面生效。


## 0.1.11：原规格与采购映射规格分行显示

SKU图旁上方以灰蓝色小字显示“原规格”，下方以深色粗体显示当前生效的完整采购映射规格。共享颜色、特殊尺码、单规格例外、手动输入、服务器读取和重置均使用与数量核对相同的映射规则更新下方标题，原规格不变。未映射时下方仍显示原值。重新加载插件并刷新1688页即可。
